# ClipShare - 剪贴板共享工具 设计文档

**日期:** 2026-07-15
**状态:** 已批准，待实现

---

## 1. 概述

ClipShare 是一款基于 Tauri 的跨平台剪贴板共享工具，允许内网用户在多台机器间实时同步复制内容（文字/图片/文件），主要用于排查问题时快速共享命令、截图等。

**目标平台:** Windows 7+ / Windows 10/11 / Linux (WSL)

## 3. 网络架构

### 3.1 混合模式

每台机器同时具备服务端和客户端能力，但**同时只能扮演一种角色**：

- **服务端**: 监听 TCP 端口（默认 9527），等待客户端连接
- **客户端**: 主动连接其他机器的 IP:端口

角色可随时切换，切换时断开当前连接。

### 3.2 消息格式

固定 12 字节头部 + Payload：

```
Offset  Size  Field
------  ----  -----
0       4     魔数 (Magic: 0x434C4950 = "CLIP")
1       1     消息类型 (Type)
2       1     压缩标志 (Compressed: 0=否 1=是)
3       6     数据长度 (Data Length, u32 big-endian)
9       2     序列号 (Sequence, u16 big-endian)
11      1     保留字节
12      N     Payload
```

### 3.3 消息类型枚举

| Type | Name | 说明 |
|------|------|------|
| 0x01 | TEXT | 文字内容，UTF-8 编码 |
| 0x02 | IMAGE | 图片内容，PNG/JPEG 原始数据 |
| 0x03 | FILE | 文件内容，二进制分块传输 |
| 0x04 | HEARTBEAT | 心跳保活，每 5 秒发送 |
| 0x05 | ACK | 块确认，序列号回执 |

### 3.4 文件传输流程

1. 发送方先发 `FILE` 消息（Payload = 文件名 + 文件大小）
2. 接收方回复 `ACK`（序列号=0）
3. 发送方分块发送文件数据，每块 64KB
4. 每块到达后接收方回复 `ACK`（携带序列号）
5. 发送方收到 ACK 后发送下一块
6. 文件最大 100MB，超过则拒绝并记录日志

### 3.5 压缩

- 文字超过 1KB 时尝试 gzip 压缩，压缩后置 Compressed=1
- 图片超过 10KB 时尝试 JPEG 压缩（质量 80%）
- 文件不压缩

## 4. 剪贴板监控

### 4.1 Windows

使用 `AddClipboardFormatListener` API，实时感知剪贴板变化，延迟毫秒级。

监控内容：
- `CF_UNICODETEXT` → 文字
- `CF_BITMAP` / `CF_DIB` → 图片（转换为 PNG）
- `CF_HDROP` → 文件列表

### 4.2 Linux (WSL/X11/Wayland)

通过子进程调用：
- Wayland: `wl-paste`
- X11: `xclip`

每 300ms 轮询一次（精度略低但兼容性好）。

## 5. 用户界面

### 5.1 窗口模型

- **主窗口**: 启动时显示，可最小化到系统托盘
- **托盘图标**: 右键菜单（打开主界面 / 切换角色 / 退出）
- **窗口尺寸**: 默认 600x500，最小 480x400

### 5.2 布局结构

```
┌──────────────────────────────────────┐
│  ClipShare          [─] [□] [×]     │  ← 标题栏
├──────────────────────────────────────┤
│  [配置]  [日志]                       │  ← Tab 导航
├──────────────────────────────────────┤
│                                      │
│  配置面板 / 日志面板 (根据 Tab)        │
│                                      │
│                                      │
└──────────────────────────────────────┘
```

### 5.3 配置面板

| 项目 | 控件 | 说明 |
|------|------|------|
| 角色 | 单选按钮 | 服务端 / 客户端 |
| 端口 | 数字输入 | 默认 9527 |
| 目标IP | IP输入 | 客户端模式可用 |
| 目标端口 | 数字输入 | 客户端模式可用 |
| 最大文件大小 | 数字显示 | 固定 100MB（只读） |
| 连接状态 | 指示灯 | 在线(绿) / 离线(灰) / 连接中(黄) |
| 操作按钮 | 按钮 | 保存配置 / 启动监听或连接 |

### 5.4 日志面板

实时日志列表（Ant Design List + Tag），每条日志包含：

- 时间 (HH:mm:ss)
- 方向标签 (发送=蓝色 / 接收=绿色 / 错误=红色)
- 数据类型图标 (文字📄 / 图片🖼️ / 文件📁)
- 内容摘要 (文字前20字 / 图片"截图" / 文件名)
- 数据大小

底部按钮：**清空当前显示**

日志颜色规则：
```
发送 (send)  → 蓝色 (#1890ff)
接收 (recv)  → 绿色 (#52c41a)
错误 (error) → 红色 (#ff4d4f)
```

## 6. 日志系统

### 6.1 日志文件

路径: `~/.clipshare/logs/YYYY-MM-DD.jsonl`

每行一个 JSON 对象：

```json
{"time":"2026-07-15T10:00:01.123","type":"send","dataType":"text","content":"hello world","size":11}
{"time":"2026-07-15T10:00:02.456","type":"recv","dataType":"file","content":"report.pdf","size":1048576}
{"time":"2026-07-15T10:00:03.789","type":"error","dataType":"","content":"连接超时","size":0}
```

字段说明：
- `time`: ISO 8601 格式时间戳
- `type`: send | recv | error
- `dataType`: text | image | file | 空（错误时）
- `content`: 文字内容 / 图片固定"截图" / 文件名 / 错误描述
- `size`: 数据字节数

### 6.2 界面日志显示

- 内存保留最近 500 条，超出后丢弃最旧的
- 点击日志条目可复制内容到剪贴板
- 清空按钮仅清屏，不删除日志文件

## 9. 错误处理

| 场景 | 处理方式 |
|------|----------|
| 连接断开 | 自动重连（最多3次，间隔2s），失败则记录错误日志 |
| 文件超过100MB | 拒绝传输，记录警告日志 |
| 剪贴板读取失败 | 跳过本次，3秒后重试 |
| 监听端口被占用 | 提示用户，切换到其他端口 |
| 心跳超时（30s无响应） | 判定连接断开，尝试重连 |

## 10. 验收标准

1. 单个 exe 文件，双击可直接运行
2. 服务端启动后客户端可连接，文字/图片/文件均可传输
3. 文件超过 100MB 显示错误，不崩溃
4. 日志同时写入文件和界面，两者颜色一致
5. 切换角色后连接断开重连
6. 最小化到托盘，点击托盘图标恢复窗口
7. 配置文件修改后下次启动自动加载
8. Windows 7 及以上可用（部分系统 API 需降级处理）
